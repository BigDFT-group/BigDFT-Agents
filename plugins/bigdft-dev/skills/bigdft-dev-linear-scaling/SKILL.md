# Linear-Scaling Optimization Internals

This is a mechanics reference, not an introduction to linear-scaling DFT -- it assumes you already know what support functions (TMBs) and a density kernel are. Every claim here is grounded in a specific file:line in `bigdft-suite` (paths relative to the `bigdft/` package root unless noted otherwise) and was verified by reading the source.

## 1. The outer SCF loop (`src/linear/linearScaling.f90`, subroutine `linearScaling`)

The whole calculation is one loop: `outerLoop: do itout=istart,nit_lowaccuracy+nit_highaccuracy`. Each outer iteration does one round of support-function optimization (`getLocalizedBasis`, section 3) followed by one round of kernel/density optimization (`scf_kernel`, an internal contained subroutine wrapping the mixing loop `kernel_loop: do it_scc=1,nit_scc`, dispatching to FOE/NTPoly/direct-minimization/diagonalization -- section 4).

### Three `target_function` values, two `nlevel_accuracy` regimes

- `TARGET_FUNCTION_IS_TRACE`, `TARGET_FUNCTION_IS_ENERGY`, `TARGET_FUNCTION_IS_HYBRID` (from `public_enums`).
- `input%lin%nlevel_accuracy == 2`: the two-level scheme. `itout==1` calls `set_optimization_variables` (`src/linear/initAndUtils.f90`, around line 1228) which sets `target_function=TARGET_FUNCTION_IS_TRACE` while `.not. lowaccur_converged`, or `TARGET_FUNCTION_IS_ENERGY` once it is. Each subsequent `itout` calls `check_whether_lowaccuracy_converged(itout, nit_lowaccuracy, input%lin%lowaccuracy_conv_crit, lowaccur_converged, pnrm_out)` (`linearScaling.f90:394`) to decide whether to flip `lowaccur_converged` from false to true -- a real, explicit convergence check on the low-accuracy phase.
- `input%lin%nlevel_accuracy == 1` ("hybrid", `lin_general.hybrid: Yes` in input.yaml): `set_variables_for_hybrid` (`initAndUtils.f90:960`) is called **once**, only at `itout==1` (`linearScaling.f90:411`), and sets `target_function=TARGET_FUNCTION_IS_HYBRID` unconditionally. `target_function` is never reassigned away from `HYBRID` anywhere in this file for the `nlevel_accuracy==1` path -- confirmed by grepping every assignment site; the only other assignments are inside the `nlevel_accuracy==2`-gated call. Hybrid mode has no "transition to high accuracy" as a distinct phase the way the two-level scheme does.
- **What ends a hybrid-mode run**: `check_for_exit` (`linearScaling.f90:2249`), `nlevel_accuracy==1` branch (line 2272): `if (pnrm_out < input%lin%highaccuracy_conv_crit) then infocode=0; exit_outer_loop=.true. else if (itout==nit_lowaccuracy) then exit_outer_loop=.true.` -- the iteration-cap branch does **not** set `infocode=0`, so it stays at its default of `1` (`linearScaling.f90:382`). `pnrm_out` is the density/potential residual from the kernel mixing loop (`printSummary`, `linearScaling.f90:2285`, prints it as `delta`). Hybrid-mode convergence is purely "is the density residual small enough yet," checked fresh every outer iteration.
- For `nlevel_accuracy==2`, `check_for_exit`'s other branch (line 2254) only evaluates once `lowaccur_converged`, and distinguishes `alpha_mix_highaccuracy /= 0` (checks `pnrm_out<highaccuracy_conv_crit` or `cur_it_highaccuracy==nit_highaccuracy`) from the `==0` case (checks `energyDiff` instead) -- a separate exit criterion from the low-accuracy one.

### `can_use_ham` -- reuse the SF-optimization Hamiltonian for kernel optimization, or not

`linearScaling.f90:706-727`: for `TARGET_FUNCTION_IS_TRACE`/`_ENERGY`, `can_use_ham` gets forced `.false.` if any `input%lin%potentialPrefac_lowaccuracy/highaccuracy(itype) /= 0.d0` -- this checks the **raw input value** (whether confinement was requested as nonzero -- `-1` "automatic" included, since `-1 /= 0`), not the actually-applied confinement magnitude. The `TARGET_FUNCTION_IS_HYBRID` case of this same check is commented out (lines 720-726), so for hybrid mode this override never runs and `can_use_ham`'s value is purely whatever `getLocalizedBasis` last set it to (section 3: driven by whether the most recent SF-optimization step increased the energy).

## 2. Confinement mechanics

- Per-orbital confinement lives in `confpot_data` (`liborbs/src/potential.f90:22`): fields `prefac` (the value actually used in the confining potential), `damping`, `potorder`, `hh`, `rxyzConf`, `ioffset`.
- Constructor `confinement_data(confpotorder, potentialprefac, lr, rxyz)` (`potential.f90:54`) unconditionally sets `damping = 1.0_gp` (line 70) whenever a fresh `confpot_data` is built.
- `set_confdatarr` (`src/linear/initAndUtils.f90:1104`) computes `prefac` per orbital/atom-type from `input%lin%potentialPrefac_lowaccuracy`/`_highaccuracy(itype)`: negative -> "automatic", `prefac = 20.d0/locrad(ilr)**4`; otherwise the literal input value (e.g. `0.0` for explicit zero-confinement). It does not multiply by `damping`. It also prints, unconditionally, the per-process `max diff damping` (max pairwise difference of `confdatarr(:)%damping` across local orbitals) and `confdatarr(1)%damping` as `damping value` -- a cheap way to check uniformity across orbitals.
- **Code-history note**: per `git blame` (commit `0b8f28f57a`, "corrected a bug in the automatic setting of the prefactor for the confinement", 2015-01-19), `set_variables_for_hybrid` used to have its own inline per-orbital loop ending in `confdatarr(iorb-orbs%isorb)%prefac=prefac*damping_factor` -- the only one of three near-identical loops (the other two, in `set_optimization_variables`'s high/low-accuracy branches, never multiplied by damping) that did this multiply. That commit consolidated all three into the shared `set_confdatarr`, which follows the two-out-of-three behavior (no damping multiply). `damping_factor` is still received as an argument by `set_variables_for_hybrid`; as of `devel` on 2026-09-29 it is not applied to `confdatarr(:)%prefac` there.
- **Restart-time damping**: `tmb%damping_factor_confinement` (scalar field on `tmb`, declared `types.f90:299`). Default `1.d0`, set in `cluster.f90:720` ("will be modified in case of a restart"). Computed in two places, both via the identical formula `tt = exp(max_shift*3.465735903d0) - 1.d0` (0 when nothing moved, saturating to 1 by `max_shift~0.2` Bohr), `min(tt, 1.d0)`:
  - `readmywaves_linear_new`/`reformat_one_fragment` (`src/modules/io.f90`) -- the **disk restart** path (`INPUT_PSI_DISK_LINEAR`, section 5).
  - `input_memory_linear` (`src/init.f90`) -- the **wavelet/in-memory restart** path (`INPUT_PSI_MEMORY_LINEAR`, section 5).
  - `max_shift` is computed by comparing atom positions embedded in the restart file's own header (`mywaves%astruct%rxyz`) against the current run's `rxyz` -- a pure geometric diff; nothing about "confinement state" needs to be written to disk for this to work.
  - `max_shift` from a floating-point position comparison is never bit-exact `0.0` for a genuinely-unmoved restart (typically ~1e-15), so the un-snapped formula leaves `damping` at e.g. `4e-15` rather than exact `0`.
- **`reduce_conf`/`ratio_deltas` ramp** (`linearScaling.f90:550-580`): a separate mechanism from restart damping, active on every outer iteration once `reduce_conf` becomes `.true.` (set at `linearScaling.f90:661`, after the first iteration). Multiplies the *existing* `confdatarr(:)%prefac` by `input%lin%reduce_confinement_factor` if positive, else by `ratio_deltas**2` (`ratio_deltas` is "kappa" from support-function optimization, section 3 -- clamped/defaulted per its sign). This is the mechanism that decays confinement iteration-to-iteration during a normal run; it multiplies whatever's already there, so it can never turn an exact `0.0` into something nonzero.
- `adjust_locregs_and_confinement` (called `linearScaling.f90:442`, only inside the `cur_it_highaccuracy==1` block, itself only reachable for `nlevel_accuracy==2`) is another confinement-adjustment point, not reached in hybrid mode.
- For hybrid mode specifically: `confdatarr` is populated exactly **once** per run (at `itout==1`) and never rebuilt from scratch afterward -- the only iteration-to-iteration change is the multiplicative ramp above. So if `prefac` is bit-exact `0.0` at `itout==1`, it provably stays exactly `0.0` for the rest of a hybrid-mode run (any code path that only multiplies an existing value can't turn a true zero into a nonzero number).

## 3. Support-function optimization (`src/modules/get_basis.f90`, subroutine `getLocalizedBasis`)

Per-outer-iteration loop (`iterLoop: do`, starting `get_basis.f90:239`) that applies the Hamiltonian, computes the orthoconstrained gradient, and steps the support functions (DIIS or steepest descent) until convergence or a failure-driven exit.

- **`kappa` is literally `ratio_deltas`** (`get_basis.f90:660`: `call yaml_map('kappa',ratio_deltas,...)`), computed (lines 641-654) only when `it>1 .and. (target_function==HYBRID .or. experimental_mode)`, as `ratio_deltas = ediff_best/delta_energy_prev` -- how well the actual energy change matches the model's predicted change. Fed into a 3-entry rolling `kappa_history` (lines 666-668) and averaged into `dynamic_convcrit` (lines 681-687) for hybrid mode's experimental dynamic-convergence-criterion path. This `kappa`/`ratio_deltas` is unrelated to CheSS/FOE's own Fermi-level solver (section 4 has a completely separate root-finding loop that happens to also be about self-consistency, but shares no code or naming with this one).
- **"Fake kappa" is exactly this**: `get_basis.f90:650-654` -- whenever `energy_increased .or. energy_increased_previous` (the last step made the trace/energy worse), `ratio_deltas` is not computed from the real energy-change ratio; instead it's hardcoded to `0.5d0`, with `call yaml_warning('use a fake value for kappa')`. A "fake kappa fallback" is therefore a direct symptom of a failed (energy-increasing) SF-optimization step. `grep -rn "fake" chess/` finds nothing -- this language is entirely local to `get_basis.f90` (support-function optimization), not kernel optimization.
- **DIIS failure recovery**: `get_basis.f90:690-817`. When `energy_increased .and. ldiis%isx==0 .and. .not.allow_increase` (a bad step with no DIIS history to fall back on), the code reverts to the previous support functions/kernel (`recovered_old_kernel=.true.`, restores `lphiold`/`kernel_best`), sets `can_use_ham=.false.`, decrements the iteration counter by 2 to retry (`it=it-2`), and after enough consecutive failures progressively disables orthonormalization (`ortho_on=.false.`) or switches to steepest descent. `ldiis%icountDIISFailureTot`/`icountDIISFailureCons` (initialized `src/linear/orbitalOptimization.f90:346-347`) count these. `nit_exit = min(nit_basis + ldiis%icountDIISFailureTot, nit_basis+6)` (line 844) -- DIIS failures buy a few extra iterations (capped at 6), not unlimited retries.
- In the no-failure branch, `can_use_ham=.true.` (line 814) -- for hybrid mode, where `linearScaling.f90`'s override is dead code (section 1), `can_use_ham` is driven entirely by whether the most recent SF-optimization step increased the energy.
- **Exit criteria** (`exit_loop(1:7)`, `get_basis.f90:856-869`), each setting `infoBasisFunctions` to a distinct signal: `(1)` net iteration cap `it>=nit_exit` -> `infoBasisFunctions=-1`; `(2)` total iteration cap `it_tot>=3*nit_basis` -> `-2`; `(3)` experimental-mode early-stop energy-difference criterion; `(4)` `fnrm_now<conv_crit` (normal gradient-norm convergence, sets `infoBasisFunctions=it`, positive/converged); `(5)` experimental dynamic-criterion path; `(6)` extended-input-guess-only kappa criterion (`itout==0` only); `(7)` dead code (`.false. .and. ...`, always skipped). `info_basis_functions<=0` is exactly what triggers the `support function optimization not converged` warning in `print_info` (`linearScaling.f90:2373`) -- i.e. the SF loop hit an iteration cap (paths 1 or 2) rather than genuinely converging on the gradient norm.
- General mechanism this explains: a shock to the support-function basis (of any origin -- confinement or otherwise) -> repeated energy-increasing SF-optimization steps -> fake-kappa fallbacks and DIIS-failure reverts -> SF optimization exhausts its iteration budget without converging (`support function optimization not converged`) -> the outer loop's own density residual (`pnrm_out`) may never get small enough either -> `itout==nit_lowaccuracy` reached with `infocode` left at its default `1`.

## 4. Kernel/coefficient optimization

Dispatched by `input%lin%scf_mode`: `LINEAR_FOE`, `LINEAR_DIRECT_MINIMIZATION`, `LINEAR_NTPOLY`, or diagonalization (`printSummary`, `linearScaling.f90:2291-2299`, labels `FOE`/`DMIN`/`NTPOLY`/`DIAG`; dispatch itself in `src/modules/get_kernel.f90`). `info_scf<0` prints `density optimization not converged` (`linearScaling.f90:2386`) -- the kernel-side analogue of `info_basis_functions<=0` (section 3), but a distinct failure mode: it means the density/kernel mixing loop didn't converge, not that the support-function gradient failed to converge.

### FOE (Fermi Operator Expansion)

Lives in CheSS (`chess/src/foe.f90`, `foe_common.f90`, `fermi_level.f90`, `foe_base.f90`), driven from `bigdft` via `get_kernel.f90`. Computes the density kernel by expanding the Fermi (occupation) function in Chebyshev polynomials of the Hamiltonian, avoiding explicit diagonalization.

- **Chebyshev fit and eigenvalue bounds**: `get_bounds_and_polynomials` (called `foe.f90:281`) builds the polynomial expansion (`chebyshev_polynomials`, degree `npl`, between `npl_min` and `npl_max` in steps of `npl_stride`) valid over the assumed spectral window `[evlow, evhigh]`. Initial bounds come from `chess.foe.eval_range_foe` (input.yaml, e.g. `[-0.5, 0.5]`) -- see `foe_common.f90:1212-1213`, `evlow_ = cp%foe%eval_range_foe(1)` -- and are reset to this input default every time `init_foe` runs (once per process). **FOE eigenvalue bounds are not preserved across a restart**: nothing in the disk-restart read path (`readmywaves_linear_new`/`reformat_one_fragment`, section 5) touches `foe_obj`/`evlow`/`evhigh`; a restarted run rebuilds and re-adapts its bounds from the same static input default as a from-scratch run, then re-adapts them during its own kernel-optimization iterations.
- **Auto-shrink logic**: `foe.f90:186-196` -- once `evbounds_isatur > evbounds_nsatur` (too many FOE cycles have passed without needing to widen the bounds) *and* `evboundsshrink_isatur <= evboundsshrink_nsatur` (a cap on how many times shrinking itself may happen), both `evlow` and `evhigh` are multiplied by `0.9` (i.e. the assumed spectral window narrows by 10%, presumably to sharpen numerical resolution once the bounds have proven wider than necessary). There is a separate, symmetric widening mechanism (`foe_common.f90:780,789`, multiplying by `factor_low`/`factor_high`) for when the assumed bounds turn out too narrow (detected via `evnoise`/`anoise`, `foe_common.f90:1645-1646`).
- **Adaptive `fscale`**: `fscale` is the decay-length ("smearing width") of the occupation function (see below). Input `chess.foe.fscale` is the starting value; `adjust_fscale: yes` (or the equivalent internal default) lets it change run-to-run, always clamped to `[fscale_lowerbound, fscale_upperbound]` (`foe.f90:220-222,242-243`). `fscale_ediff_low`/`fscale_ediff_up` are documented as bounds on the "optimal relative energy difference between the kernel and the control kernel" -- i.e. they gate whether the *current* `fscale` is judged too aggressive or too conservative based on a secondary "check" kernel computed at `fscale_check = CHECK_RATIO*fscale` (`foe.f90:244`) using a separate Chebyshev fit (`npl_check`, `foe.f90:319-332`) purely to validate the primary result, not to change it directly.
- **`occupation_function`**: an integer code from `module_func` (`chess/src/foe_common.f90` module `module_func`, constants at the top of that file): `101`=`FUNCTION_POLYNOMIAL`, `102`=`FUNCTION_ERRORFUNCTION` (the default seen in practice -- a smoothed step via the complementary error function, centered at `ef` with width `fscale`), `103`=`FUNCTION_XTIMESERRORFUNCTION`, `104`=`FUNCTION_EXPONENTIAL` (used specifically for the eigenvalue-bound *penalty* function, not the main occupation smearing -- see `betax` below), `105`=`FUNCTION_ERRORFUNCTION_ENTROPY`, `106`=`FUNCTION_FERMIFUNCTION`, `107`=`FUNCTION_FERMIFUNCTION_ENTROPY`.
- **`betax_foe`/`betax_ice`**: exponents for an exponential penalty function (`FUNCTION_EXPONENTIAL` case of `func_set`, `foe_common.f90:76-83`) applied outside the trusted `[evlow, evhigh]` window, used to detect when the Chebyshev expansion's estimated occupation strays outside the assumed spectral bounds (feeding `accuracy_penalty`). `betax_foe` is consumed by the main FOE kernel calculation (`initAndUtils.f90:53`, passed to CheSS's `init_cp`-style setup); `betax_ice` is the analogous parameter for **ICE** (`chess/src/ice.f90`), a parallel Chebyshev-expansion module used to compute the overlap matrix's inverse square root (`S^-1/2`, needed to transform the generalized eigenvalue problem into standard form) via the same general machinery, not the Fermi/occupation function. `accuracy_foe`/`accuracy_ice`/`accuracy_penalty`/`accuracy_entropy` are the corresponding required-accuracy thresholds for the Chebyshev fit in each of these contexts (main FOE occupation fit, ICE's overlap inverse-sqrt fit, the exponential penalty fit, and the entropy-function fit respectively).
- **Fermi-level (`eF`) determination**: `chess/src/fermi_level.f90`, `determine_fermi_level`/`init_fermi_level`, a root-finder (on `eF`) driven purely by matching a target electron count -- entirely separate from the outer BigDFT loop and from `get_basis.f90`'s kappa. Internal solver iteration count is `f%it_solver`, tracking up to 4 historical `(eF, charge-target_charge)` pairs (`interpol_matrix`/`interpol_vector`). Method selection (`determine_new_fermi_level`, `fermi_level.f90:247-371`):
  - Once `it_solver>=4`: attempts a **cubic** polynomial fit through the last 4 points, solved via LAPACK `dgesv`. Gated by three checks: (a) `abs(det) > ef_interpol_det` -- the 4-point interpolation matrix's determinant must be above this threshold, or the fit is numerically unreliable and skipped (`cubicinterpol_possible=.false.`); (b) `abs(sumn - target_charge) < ef_interpol_chargediff` -- only trust any interpolation-based extrapolation once already close to the target charge; (c) a sanity check that the cubic root moves `eF` in the physically expected direction given whether the charge was too high or too low (`interpolation_nonsense`). Logged as `new eF: cubic interpol`.
  - If the cubic fit is disallowed by any of the above: falls back to **linear** interpolation using just the last 2 points (a secant-style solve for the zero of a line). Logged as `new eF: linear interpol`.
  - If `it_solver<4` (not enough history yet), or gate (b) above fails: falls back further to **bisection**, optionally averaged with the **secant method** if the last two charge estimates differ enough to be numerically stable (`abs(sumnarr(2)-sumnarr(1))>1e-6`). Logged as `new eF: bisection/secant` or plain `new eF: bisection`.
  - This is a completely different concept from `get_basis.f90`'s kappa/fake-kappa (section 3); the two happen to share the word "fallback"/self-correction in spirit but not code, naming, or purpose -- one finds a chemical potential given a fixed spectrum estimate, the other judges a support-function optimization step's quality.

### NTPoly (density-matrix purification)

`input%lin%scf_mode==LINEAR_NTPOLY` (`get_kernel.f90:509`) calls `ntpoly_solve` (`chess/bigpoly/bigpoly_solvers.f90:133`), which converts the Hamiltonian/overlap into NTPoly's own matrix representation (`constructprocessgrid`, `overlap_step`, `density_step`) and delegates the actual density-matrix purification recursion to the external NTPoly library (a separate jhbuild module, `ntpoly-v3.1.1` in this suite's dependency chain) -- BigDFT/CheSS's own code here is a thin data-marshalling wrapper (`ntpoly_to_chess` converts the result back), not a reimplementation of the purification algorithm itself. Unlike FOE, this approach does not do an explicit Fermi-level root-find at the BigDFT/CheSS level; the target electron count is passed directly into `density_step` (`0.5_mp * nel` per spin channel) and NTPoly's internal purification iteration handles convergence to the correct trace internally.

### Direct minimization

`input%lin%scf_mode==LINEAR_DIRECT_MINIMIZATION` (`get_kernel.f90:323`) optimizes the KS expansion coefficients directly (not the density kernel/matrix), via gradient-based steps in coefficient space: `lin_kernel.nstep` (steps per outer iteration), `idsx_coeff` (DIIS history length for the coefficient optimization -- input-key documentation notes a known problem when nonzero, so `0`/pure steepest-descent is the commonly-used setting), `alpha_sd_coeff` (steepest-descent step size), `alpha_fit_coeff` (whether to fit a quadratic to adapt the step size), `coeff_scaling_factor`. Because this method works with explicit coefficients rather than a kernel/matrix, its restart data format differs from FOE/NTPoly's (section 5): a restart must set `kernel_restart_mode: 1` ("coefficients") rather than the kernel-based default, or the coefficients are not actually initialized from the restart data.

## 5. Restart mechanics

- **`inputpsiid`** selects the overall input-wavefunction policy at the top level (`init.f90`'s big `select case`), including `INPUT_PSI_LINEAR_AO` (fresh atomic-orbital guess), `INPUT_PSI_MEMORY_LINEAR` (in-memory/wavelet reformatting restart, via `input_memory_linear`), and `INPUT_PSI_DISK_LINEAR` (disk restart, via `readmywaves_linear_new`). The policy actually taken is echoed in the log as e.g. `Policy: Reading Wavefunctions from disk` (disk) vs `Policy: Support functions Restart` (memory/wavelet) vs `Policy: Input Wavefunctions Creation` (fresh AO guess) -- a reliable way to confirm from a log alone which path a given run actually took, since the same static `inputpsiid` input value can correspond to either restart path depending on which restart files are actually found on disk at read time (a missing expected file silently falls through to the fresh-AO-guess policy instead of erroring).
- **`output_wf`** (write side) is a two-digit code: units digit is the file *format* (`0`=none, `1`=plain text, `2`=Fortran binary, `3`=ETSF/NetCDF), tens digit `2` additionally writes an "Interpolating Scaling Function" (real-space grid, `.cube`-suffixed) representation alongside the primary format -- purely an auxiliary/visualization output, not itself a distinct restart-readable format (`readmywaves_linear_new` reads the primary-format files, not the `.cube` companions). E.g. `21` = plain text plus cube companion; `2` = Fortran binary only.
- **`kernel_restart_mode`** (read side) selects what the density-kernel-vs-coefficient restart data actually represents: `0`=kernel (matches FOE/NTPoly, which operate on the density matrix directly), `1`=coefficients (matches direct minimization, which optimizes coefficients directly), `2`=random, `3`=diagonal, `4`=full kernel, `5`=full coefficients. Mismatching this against the active `scf_mode` (e.g. requesting kernel-mode restart while running direct minimization) does not error; it silently leaves the coefficients/kernel effectively uninitialized, producing a nonsensical result while still reporting `infocode: 0`.
- What's read back and what isn't, by restart path: both `INPUT_PSI_DISK_LINEAR` and `INPUT_PSI_MEMORY_LINEAR` read the support-function coefficients/wavefunctions and the kernel/coefficient matrices (per `kernel_restart_mode`). Neither path restores CheSS/FOE's internal eigenvalue-bound state (`foe_obj`/`evlow`/`evhigh`, section 4) or DIIS/mixing history for either the support-function optimizer (`ldiis`) or the kernel mixing loop -- both are always rebuilt/reset fresh at the start of a restarted run, identically to a from-scratch run's initial state.
